# 智趣训练

> 一款专注力训练游戏合集 —— 微信小程序原生开发 + 腾讯云 CloudBase，**零 npm 依赖、无构建工具、无第三方 Key**。

![platform](https://img.shields.io/badge/platform-WeChat%20MiniProgram-07C160)
![backend](https://img.shields.io/badge/backend-CloudBase-0052D9)
![license](https://img.shields.io/badge/license-MIT-blue)
![deps](https://img.shields.io/badge/npm%20deps-0-success)

「智趣训练」把 5 类经典认知训练做成了小程序：舒尔特方格、数字华容道、数独、积木迷阵、数字记忆。项目完整实现了**账号体系、训练记录云端同步、难度逐级解锁、儿童模式（时长限制 + 密码保护）、激励视频/插屏广告**这套通常要写很多胶水代码的东西，代码量不大但五脏俱全，适合作为小程序 + CloudBase 的完整参考实现，也适合直接改成自己的训练类产品。

## 功能一览

### 五款游戏

| 游戏 | 玩法 | 关卡规模 |
|---|---|---|
| **舒尔特方格** | 按顺序找出乱序排列的数字，训练视觉搜索与注意力 | 8 种模式 × 8 级难度（3×3 ~ 10×10）+ 闯关模式 |
| **数字华容道** | 滑块拼图，把数字按顺序归位 | 规格 3×3 ~ 10×10，9×9 / 10×10 需解锁且消耗 VIP 次数 |
| **数独** | 经典九宫格，含技巧分级说明与难度评级 | 5 档难度，大师级需 VIP 次数 |
| **积木迷阵** | 6×6 棋盘上移动积木达成目标形状，记录最少步数 | 100 关，easy / medium / hard 三档 |
| **数字记忆** | 数字闪现后按顺序回忆点击 | 34 关，第 N 关有 N+2 个数字 |

### 舒尔特 8 种训练模式

| 模式 | key | 规则 | 初始状态 |
|---|---|---|---|
| 经典 | `classic` | 从 1 开始按顺序点击 | 已解锁 |
| 干扰 | `interference` | 彩色背景下的抗干扰训练 | 已解锁 |
| 换位 | `shuffle` | 点对后数字重新排列 | 已解锁 |
| 倒序 | `reverse` | 从大到小倒序点击 | 已解锁 |
| 奇偶 | `parity` | 只点奇数或只点偶数 | 已解锁 |
| 限时 | `challenge` | 每一步限时 2 秒 | 需解锁 |
| 字母 | `alphabet` | 按顺序点 A~Z | 需解锁 |
| 记忆 | `memory` | 先记忆、再隐藏、再按顺序点 | 需解锁 |

### 舒尔特 8 级难度

| 难度 | key | 规格 | 难度 | key | 规格 |
|---|---|---|---|---|---|
| 基础 | `base` | 3×3 | 高阶 | `unique` | 7×7 |
| 初阶 | `primary` | 4×4 | 极限 | `matchless` | 8×8 |
| 标准 | `high` | 5×5 | 疯狂 | `sky` | 9×9 |
| 中阶 | `super` | 6×6 | 宗师 | `crazy` | 10×10 |

完成当前难度后逐级解锁；正确率按**不重复的错误数值**统计（同一个数字点错多次只算一次），比「点错次数 / 总点击」更贴近真实的搜索能力。

### 通用能力

| 能力 | 实现说明 |
|---|---|
| 账号体系 | 微信 `openid` 静默登录，首次登录自动建用户与进度记录 |
| 数据双写 | 未登录写本地 `wx.storage`，登录后写云端并清理本地缓存；统计页本地与云端合并 |
| 难度解锁 | `level_progress` / `pass_progress` 两张进度表，服务端判定 |
| 儿童模式 | 1~30 分钟时长限制、6 位密码、累计计时、跨天归零、超时弹窗 |
| 参考标准 | 按年龄段与规格给出用时参考，判断快慢 |
| 音效震动 | 总开关 + 6 套独立设置（5 款游戏 + 舒尔特闯关），本地与云端双向同步 |
| 广告 | 激励视频（解锁 VIP）/ 自定义贴片 / 插屏，广告位可在配置里留空关闭 |
| 适配 | 手机竖屏 + iPad 横屏，棋盘最大化不出现滚动条 |

## 技术架构

| 层 | 选型 |
|---|---|
| 前端 | 微信小程序原生框架（基础库 3.15.2），**无框架、无构建、无 npm** |
| 后端 | 腾讯云 CloudBase：云函数（Node.js 18）+ 云数据库 + 云存储 |
| 数据访问 | 前端**不直连数据库**，全部经 21 个云函数，权限可锁到最严 |
| 状态 | `wx.storage` 本地缓存 + 内存缓存两级，减少云函数调用 |
| 资源 | 图片走云存储 `cloud://`，分享卡片图可替换 |

```
┌──────────── 微信小程序（miniprogram/）────────────┐
│  主包 11 页：游戏大厅 / 舒尔特 / 记录 / 我的 / 设置  │
│  4 个分包：华容道 · 数独 · 积木迷阵 · 数字记忆       │
│  进入首页即预加载全部 4 个分包                        │
└───────────────────┬──────────────────────────────┘
                    │ wx.cloud.callFunction（唯一通道）
┌───────────────────▼──────────────────────────────┐
│           云函数 21 个（cloudfunctions/）          │
│  save*Record / get*Records · login · unlockNewLevel│
│  统一 cloud.DYNAMIC_CURRENT_ENV，部署即用，零配置    │
└───────────────────┬──────────────────────────────┘
                    │
┌───────────────────▼──────────────────────────────┐
│   云数据库 9 集合：users / *_records / *_progress   │
└──────────────────────────────────────────────────┘
```

**几个刻意的设计选择：**

1. **不做前端直连数据库** —— 所有读写走云函数，好处是集合权限能设成 `{"read": false, "write": false}`，业务规则（谁能改谁的数据、解锁条件）天然在服务端。
2. **云函数零配置** —— 21 个函数全部 `cloud.DYNAMIC_CURRENT_ENV`，换环境不用改代码，这也是本项目只为使用者留 2 个必填值的前提。
3. **配置集中到 `miniprogram/config.js`** —— 环境 ID、云存储桶、广告位只有一个来源，页面里出现 `adunit-` 或 `cloud://` 字面量视为错误。
4. **无构建链路** —— 没有 webpack/vite/tsc，开发者工具打开就能编译；代价是不能用 npm 包，但这类小游戏不需要。

## 快速开始

```bash
git clone https://github.com/pwping/ShuET-games.git
# 微信开发者工具 → 导入项目 → 选择项目根目录（不是 miniprogram/）
```

然后只需要填 **2 个值**：

| 填什么 | 位置 |
|---|---|
| 小程序 AppID | `project.config.json` → `appid` |
| 云开发环境 ID | `miniprogram/config.js` → `envId` |

接着建 9 个数据库集合、部署 21 个云函数，即可运行。

- **人工部署**：看 [DEPLOY.md](DEPLOY.md)（分步操作 + 验收清单 + 8 条故障排查）
- **让 AI 助手部署**：把仓库丢给任意 AI 编码工具，说一句

  > 按 AGENTS.md 的部署协议把项目跑起来

  它会读 [AGENTS.md](AGENTS.md) 第 0 节，主动问你要 AppID 和环境 ID，然后给出建表清单、指路部署云函数、逐项验收。

## 配置项

全项目只有 2 个文件需要改，其余都能留空跑通。

| 配置 | 位置 | 必填 | 留空的后果 |
|---|---|---|---|
| 小程序 AppID | `project.config.json` → `appid` | ✅ | 无法编译 |
| 云开发环境 ID | `miniprogram/config.js` → `envId` | ✅ | 所有云函数调用失败 |
| 云存储桶名 | `miniprogram/config.js` → `storageBucket` | ⬜ | 分享卡片退化为微信默认截图 |
| 3 个广告位 | `miniprogram/config.js` → `adUnits` | ⬜ | 不展示广告，游戏功能不受影响 |

```js
// miniprogram/config.js
const envId = '你的云开发环境ID';
const storageBucket = '';        // 可留空
const adUnits = {
  reward: '',                    // 激励视频
  custom: '',                    // 自定义贴片
  interstitial: ''               // 插屏
};
```

> AppID 和环境 ID **都不算密钥**，公开无风险：别人没有你环境的权限，调不到你的云函数。本项目不含任何第三方 API Key，也不需要 `.env`。

## 数据库

9 个集合，全部以 `openid` 为查询键：

| 集合 | 用途 |
|---|---|
| `users` | 用户账号（昵称、头像） |
| `train_records` | 舒尔特训练记录 |
| `level_progress` | 舒尔特难度解锁进度 |
| `pass_progress` | 闯关模式进度 |
| `challenge_records` | 闯关记录 |
| `huarong_records` | 数字华容道记录 |
| `sudoku_records` | 数独记录 |
| `movingBlock_records` | 积木迷阵记录 |
| `memoryGame_records` | 数字记忆记录 |

字段定义、12 条索引（含 3 条唯一索引）、权限规则见 [DATABASE.md](DATABASE.md)。

两个容易踩的点：

- **集合建空的即可**，CloudBase 是文档型数据库，字段由代码首次写入自动生成，不需要建表语句。
- **`createTime` 有两种类型**：用户与进度表用 `db.serverDate()`（Date），记录表用 ISO 字符串——记录表要按它排序，类型混用会导致时间线错乱。

```

├── miniprogram/                  小程序前端

│   ├── app.js                    入口：云开发初始化 + 儿童模式计时器
│   ├── app.json                  路由、分包、分包预加载
│   ├── app.wxss                  全局样式
│   ├── pages/                    主包 11 页
│   │   ├── game-select/          游戏大厅（入口页）
│   │   ├── index/ level/ game/ result/    舒尔特四页
│   │   ├── challenge/ pass/      闯关模式与进度
│   │   ├── history/ mine/        历史记录、个人中心
│   │   ├── settings/ intro/      设置、介绍
│   │   ├── huarongDao/           数字华容道（分包）
│   │   ├── movingBlocks/         积木迷阵（分包）
│   │   ├── sudoku/               数独（分包）
│   │   └── memoryGame/           数字记忆（分包）
│   ├── components/               6 个在用组件（年龄段选择、隐私授权、超时弹窗等）
│   ├── utils/                    缓存、设置同步、评级数据、数独评级
│   └── data/game-config.js       模式与难度定义
├── cloudfunctions/               21 个云函数，每个独立部署
├── scripts/                      关卡求解与校验脚本（纯本地算法）
├── design-system/                设计规范
├── docs/                         补充文档
├── project.config.json           ★ 项目配置（AppID、目录指向）
├── DEPLOY.md                     部署指南
├── DATABASE.md                   数据库字段与索引
├── AGENTS.md                     给 AI 助手的项目上下文与部署协议
```

**分包策略**：4 个游戏分包在进入游戏大厅时一次性预加载（`preloadRule` 挂在 `pages/game-select`），换取进入游戏零等待；主包只保留大厅与舒尔特。

## 常见问题

**Q：必须用云开发吗？能不能去掉后端？**
A：可以只保留本地存储——`utils` 与各页面已做「未登录写本地」的分支，但账号、多端同步、进度云端存档会失效。云开发有免费额度，个人项目基本够用。

**Q：没有流量主权限，广告位怎么填？**
A：留空字符串即可，广告不展示，游戏流程完全正常。

**Q：为什么前端不直连数据库？**
A：见[技术架构](#技术架构)第 1 条。代价是所有查询都得写成云函数，收益是权限模型干净、业务规则不可绕过。

**Q：改动后小程序白屏 / 云函数报 `FunctionName not found`？**
A：先查 [DEPLOY.md 的常见故障表](DEPLOY.md#常见故障)，90% 是集合没建全或云函数没部署完。

**Q：能改成其他游戏吗？**
A：可以。新增游戏的模式是：加分包目录 → `app.json` 注册 `subPackages` 与 `preloadRule` → 加 `save<Game>Record` / `get<Game>Records` 两个云函数 → 建对应集合。`AGENTS.md` 里记了这套约定和几个必踩的坑。

## 参与开发

- 提交前请确认：`miniprogram/` 与 `cloudfunctions/` 下所有 js 通过 `node --check`
- 不要在页面里硬编码 `adunit-` / `cloud://` / 环境 ID，一律走 `config.js`
- 修某个游戏的问题时不要动其他游戏的正常逻辑，出现回归优先回滚或打局部补丁
- 详细约定与已知坑见 [AGENTS.md](AGENTS.md)

Issue 和 PR 都欢迎。
